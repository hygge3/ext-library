ext-library

Spring Boot 开发者的瑞士军刀
26 个即插即用模块，覆盖缓存、安全、加密、实时通信等企业级通用能力

☕ JDK 25 🍃 Spring Boot 4.1 📦 v4.1.0 🧱 Gradle 9.8.1 📄 Apache-2.0
GitHub 快速开始 架构分层

为什么选择 ext-library？

把每个项目都要重写一遍的通用能力，收敛成统一风格的模块

🧩

按需引入

26 个独立模块，互不牵连。只依赖你真正用到的部分，ext-tool 零第三方依赖，不会给应用带来任何负担。

🎯

一致的 API

统一的自动配置入口、配置前缀（ext.{module}）与命名约定。学习一个模块的用法，即可掌握其余全部。

⚡

面向现代 Java

基于 JDK 25 虚拟线程与 Spring Boot 4.1 构建，HTTP 客户端默认走虚拟线程执行器，实时通信支持分布式扩展。

🔐

安全与加密

注解驱动的认证授权框架，配合国密 SM2/SM3/SM4 与 AES/RSA 工具库，请求解密、响应加密均可注解一行搞定。

💾

基础设施可替换

多级缓存抽象兼容 Caffeine、Redis 与 PostgreSQL；Redis 能力（缓存、队列、发布订阅、限流）均提供 PG 实现。

📡

实时通信

SSE 单向推送与 WebSocket 全双工两套通道，均内置 pubsub 支持多实例分布式部署。

清晰的架构分层

上层依赖下层，同层可相互依赖，下层不反向依赖上层

业务增强层

注解 + AOP 无侵入扩展

↑

Web 层

统一请求处理、API 文档、实时通信
ext-mvc ext-realtime
↑

安全 / 加密层

认证授权与密码学算法
ext-security ext-crypto
↑

基础设施层

与外部基础设施集成
ext-redis ext-cache ext-mail ext-postgres
↑

通用基础层

所有模块的直接或间接依赖
ext-tool ext-core ext-json

模块生态

统一由 ext-bom 管理版本，坐标均为 ext.library:{模块名}

快速开始

引入 BOM 统一版本管理后，按需声明模块依赖即可

build.gradle 
dependencies {
    implementation platform('ext.library:ext-bom:4.1.0')
    implementation 'ext.library:ext-core'
}
pom.xml 
<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>ext.library</groupId>
            <artifactId>ext-bom</artifactId>
            <version>4.1.0</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>

<dependencies>
    <dependency>
        <groupId>ext.library</groupId>
        <artifactId>ext-core</artifactId>
    </dependency>
</dependencies>

模块均由 Spring Boot 自动配置装配，引入依赖后无需额外声明配置文件
